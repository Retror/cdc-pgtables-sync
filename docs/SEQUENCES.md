# 序列（sequence）与标识列：会不会同步？要不要手动处理？

## 结论

**序列的当前值不会同步。** 无论是 `init` 全量复制，还是 `run` 增量同步，目标库上的序列都不会跟着源库变化。

但**日常同步期间，这不会造成任何问题，也不需要处理**：pglsync 写入目标库时，`id` 等列用的都是源库的原值，根本不会调用目标库的序列。

**只有当目标库自己要生成新的 id 时**（最典型的是把目标库切换成主库、开始直接接收业务写入），才需要把目标库的序列调整到正确的位置，否则新插入的数据会和已有的 id 冲突。

---

## 1. 为什么序列不会同步

| 环节 | 序列的情况 |
|---|---|
| 建表（`pg_dump -s`） | 只导出表结构和序列的定义，**不导出序列的当前值**。序列的当前值属于数据部分，`-s` 不包含 |
| `init` / `resync`（`COPY`） | 复制的数据里带着源库原来的 `id`。显式提供了值，就不会调用 `nextval()`，所以目标库序列不会前进 |
| `run`（增量同步） | 同样写入源库的原值。PostgreSQL 的逻辑复制本身也不传输序列的变化（PG17 及以前都是如此） |
| `init --no-copy` | 目标库序列保持原来的值，取决于目标库当初是怎么建出来的（比如用 `pg_dump` 连数据一起导入时，序列也会被设置好） |

所以，`init` 之后目标库的序列通常还停在初始值（比如 1），而表里已经有大量 id 了。

---

## 2. 什么时候需要处理

| 场景 | 是否需要调整目标库序列 |
|---|---|
| 目标库只由 pglsync 写入（正常同步期间） | **不需要** |
| 目标库只读，用于查询、报表 | **不需要** |
| 把目标库切换为主库（迁移、灾备切换），之后由业务直接写入 | **需要**，见第 3 节 |
| 有人或程序直接往目标库插数据，并且依赖序列生成 id | **需要**。不过同步期间不应该直接写目标库，否则数据会和源库不一致 |

不处理的后果：目标库上 `nextval()` 会返回一个已经被占用的 id，插入时报 `duplicate key value violates unique constraint`。

---

## 3. 怎么调整目标库的序列

两种方法任选其一。**切换为主库时推荐方法 A。**

### 方法 A：把源库序列的当前值搬到目标库（推荐）

这种方法保留了源库序列的实际进度。源库因为删除、事务回滚、序列缓存等原因，序列值往往比表里的最大 id 还大，用源库的值最稳妥。

**① 在源库生成设置语句**（先停止业务写入，保证序列不再变化）：

```sql
-- 在源库（131）执行，输出的每一行都是一条 SQL
SELECT format('SELECT setval(%L, %s, true);', schemaname || '.' || sequencename, last_value)
FROM pg_sequences
WHERE schemaname = 'public' AND last_value IS NOT NULL
ORDER BY 1;
```

输出类似：

```
SELECT setval('public.tcensemblerealtime_id_seq', 14300511, true);
SELECT setval('public.base_common_dict_id_seq', 356, true);
...
```

**② 把这些语句拿到目标库执行**：

```bash
# 一步完成：在源库生成语句，直接在目标库执行
psql -h 192.168.234.131 -U postgres -d typhoon -At -c "
  SELECT format('SELECT setval(%L, %s, true);', schemaname || '.' || sequencename, last_value)
  FROM pg_sequences WHERE schemaname = 'public' AND last_value IS NOT NULL" \
| psql -h 192.168.234.132 -U postgres -d typhoon
```

`last_value IS NOT NULL` 用来排除从未使用过的序列，这些序列在目标库保持初始值即可。

### 方法 B：按目标库表中的最大值设置

不方便访问源库，或者只想保证不冲突时使用。下面的语句会找出 `public` 下**所有属于某张表某一列**的序列（包括 `serial`/`bigserial` 和标识列），把它们设置为“该列当前最大值 + 1”：

```sql
-- 在目标库（132）的 psql 中执行；\gexec 会依次执行查询结果中的每条语句
SELECT format('SELECT setval(%L, COALESCE((SELECT max(%I) FROM %s), 0) + 1, false);',
              s.oid::regclass, a.attname, t.oid::regclass)
FROM pg_class s
JOIN pg_depend d    ON d.objid = s.oid AND d.classid = 'pg_class'::regclass
                   AND d.refclassid = 'pg_class'::regclass AND d.deptype IN ('a', 'i')
JOIN pg_class t     ON t.oid = d.refobjid
JOIN pg_attribute a ON a.attrelid = t.oid AND a.attnum = d.refobjsubid
WHERE s.relkind = 'S' AND t.relnamespace = 'public'::regnamespace
\gexec
```

`setval(序列, max + 1, false)` 表示下一次 `nextval()` 返回 `max + 1`。表为空时会设为 1。

> 对大表求 `max(id)` 时，`id` 列上有索引（比如主键）就会很快。超表的主键是 `(id, datatime)`，`id` 是主键的第一列，同样可以利用索引。

### 验证

```sql
-- 在目标库对比：序列的 last_value 应 >= 表中的最大 id
SELECT last_value FROM public.tcensemblerealtime_id_seq;
SELECT max(id) FROM public.tcensemblerealtime;
```

## 4. 切换为主库时的完整顺序

如果打算把目标库切换为主库（比如迁移到新库），序列只是其中一步。完整顺序是：

1. **停止源库的业务写入**；
2. **等同步追上**：`status` 中“落后”接近 0，日志中没有正在应用的大事务；
3. **核对数据**：`reconcile` 全部一致；
4. **停止 pglsync**，然后执行 `drop` 删除源库上的复制槽（否则源库会一直保留 WAL）；
5. **调整目标库序列**：用第 3 节的方法 A；
6. 如果源库的表上有业务触发器、而目标库建表时删掉了，**按需在目标库补建**；
7. **把业务连接切换到目标库**。

## 5. 标识列（IDENTITY）的说明

除了 `serial`/`bigserial`，有些表的 id 用的是**标识列**：

```sql
id bigint GENERATED BY DEFAULT AS IDENTITY   -- 允许显式写入值
id bigint GENERATED ALWAYS AS IDENTITY       -- 默认不允许显式写入值
```

| 标识列类型 | 同步时的情况 |
|---|---|
| `GENERATED BY DEFAULT` | 和 `serial` 一样，可以直接写入源库的原值 |
| `GENERATED ALWAYS` 并且是主键 | 普通 INSERT 显式写入值会报错。**pglsync 写入时已加上 `OVERRIDING SYSTEM VALUE`**，可以正常写入源库的原值；`init` 使用的 COPY 本身也允许写入 |
| `GENERATED ALWAYS` 但不是主键 | 更新这一列时会报错 `column ... can only be updated to DEFAULT`。建议在**目标库**上改为 `GENERATED BY DEFAULT`：`ALTER TABLE 表名 ALTER COLUMN 列名 SET GENERATED BY DEFAULT;` |

标识列背后也是一个序列，同样不会同步。需要时用第 3 节的方法调整，方法 B 的查询已经包含了标识列的序列。

## 6. 速查

| 问题 | 答案 |
|---|---|
| `init` 会同步序列的当前值吗？ | 不会 |
| `run` 会同步序列的当前值吗？ | 不会 |
| 同步期间需要手动调整目标库序列吗？ | 不需要，pglsync 写入的都是源库的原值 |
| 什么时候必须调整？ | 目标库要自己生成 id 时，比如切换为主库 |
| 用什么值调整最稳妥？ | 源库序列的当前值（方法 A） |
